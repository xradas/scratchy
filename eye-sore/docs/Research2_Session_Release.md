## Primary research and transferable choices

RF SDL distinguishes application data location from writable per-user path. `SDL_GetBasePath` may be null and has platform bundle semantics; `SDL_GetPrefPath` provides user/app writable storage. **P:** resolve packaged data once and separately choose writable preferences/log/save destinations. No writes beside executable. [SDL base path](https://wiki.libsdl.org/SDL2/SDL_GetBasePath), [SDL preference path](https://wiki.libsdl.org/SDL2/SDL_GetPrefPath).

RF XDG separates configuration, data, state and cache, with absolute overrides and defined defaults. **P:** a Linux adapter may use config for preferences, data for saves, state for bounded logs/capture index and cache for regenerated assets; select either this explicit adapter or SDL's portable preference root consistently, not two competing stores. External requested capture output is its own explicit path. [XDG specification](https://specifications.freedesktop.org/basedir/latest/).

RF SDL exposes focus/minimize/display-size window events and audio-added/removed events; removal identifies an opened device while addition uses a device index. **P:** pause on keyboard focus loss; identify the affected output device before recovery, never accidentally select a microphone. [Window events](https://wiki.libsdl.org/SDL2/SDL_WindowEventID), [Audio device events](https://wiki.libsdl.org/SDL2/SDL_AudioDeviceEvent). RF GL context creation can fail/null. **P:** check before issuing GL calls and preserve readable errors. [SDL context docs](https://wiki.libsdl.org/SDL2/SDL_GL_CreateContext).

RF Linux Doom save code archives players, world, thinkers and special states; pointer/structure-specific serialization in that snapshot requires careful reconstruction. **I:** saving only player HP/location is insufficient. **P:** stable semantic IDs and explicit versioned records instead of raw struct pointers, per role18. No copying of Doom source or save format is proposed. [id save reference](https://raw.githubusercontent.com/id-Software/DOOM/master/linuxdoom-1.10/p_saveg.c).

RF Valve advises building within its runtime containers to avoid build-host library leakage; its runtime goals describe library/driver compatibility constraints. **P:** if distributing through Steam later, choose a supported runtime/SDK deliberately; for the current local packet, choose a named Linux/glibc baseline and test there. A newer local binary is not retroactively made compatible by packing libraries blindly. No Steam release/Steam Deck support is implied. [Valve runtime project](https://github.com/ValveSoftware/steam-runtime), [runtime goals](https://github.com/ValveSoftware/steam-runtime/blob/master/doc/goals.md).

RF Godot's Linux export produces a runtime binary/data package using export settings/templates; export targets vary by architecture. **P:** if role01 chooses Godot, use that export pipeline and retain semantic build/content/profile IDs, rather than preserve native Makefile as a shadow release. Export alone does not verify asset inclusion or graphics/audio compatibility. [Godot Linux export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_linux.html).

RF SDL2+ uses zlib license; FFmpeg's effective license depends on compiled components/options, with GPL optional parts. **P:** inventory exact shipped library/tool versions/notices and decide whether capture encoder is a separately installed developer tool. Do not infer the game's license merely from invoking a process; equally, do not redistribute an arbitrary libx264-enabled FFmpeg binary without its applicable evidence/obligations. ## Exact supported M0/C session loop

P first experiment packet supports fresh launch, one declared profile, full retry, pause/help/map/options, death, valid exit result and quit. The ready-paused flow below describes the **automated/manual M0/C experiment harness**, not an approved finished-game opening. M0 is the isolated matched Hold/Cross room; C is S–T–P–M–X plus optional O, both flat. Profile records actual initial weapons/ammo/seed: role05's abundant finite diagnostic ammo is proposed, whereas current native ammo is unlimited. Neither must secretly change between calibration and standard play.

```text
Boot → Validate/load bundle → Ready paused → explicit Start → Playing
                      failure ↓                         ↓ focus/pause
                      Error                          Paused
Playing → Death result / valid Exit result          ↙ resume
Result → Retry full profile / Back to ready / Quit
Paused → Resume / Options / Map / Retry / Quit
Quit → stop producers → close audio/capture → free resources → exit
```

**Harness entry hypothesis:** validate selected seed/config/content without player ceremony, initialize a coherent snapshot, then remain paused until the operator's Start/run command. A manual review may show one small ready card naming profile/retry scope; automated fixtures can start via their logged command with no card. Capture/session metadata is in the operator log, not necessarily the player's view. This deliberate ready boundary lets comparisons begin from the same state and does not impose a startup pause on the released game.

**Player-facing first-boot hypothesis:** after validation/loading, offer a minimal direct Start path with controls/options available, or enter the safe opening immediately once focus/input readiness is established if UI/play review finds that better. Later Continue is available only when a valid supported saved session exists; current M0/C has no disk resume. Avoid a mandatory profile/seed/capture checklist or a separate ready card on every retry. The selected flow must preserve readable options and safe mouse capture/held-input handling, but need not require an extra confirmation to begin. Direct retry can reset and return immediately to the approved safe start; operator-controlled harness retry may remain paused for comparison.

These are flow hypotheses for role17 and player review. They authorize neither a launcher nor a full title-menu system. Shared lifecycle validation, generation/reset and input safety apply whichever player entry is chosen. Required load errors name the resource/state and allow Quit; intentionally disabled optional ambience/score stays absent, while unexpected required attack-cue failure blocks its declared audio-review mode.

**Fresh start:** freeze approved profile/content versions and seed; create run generation; initialize feet/camera, HP/loadout/ammo, actors, encounter state, pickups/doors/exits/knowledge, timers and RNG streams; publish one coherent initial snapshot; if the profile enables score/ambience, reset its music to authored entry and world beds to declared positions; keep intentionally disabled buses/cues disabled; start simulation only after all required services are ready. Both weapons owned in initial C comparison per role05; no inherited cache unlock requirement.

**Retry:** return to profile initial state with same seed by default for comparisons, new generation and cleared input. Whole room/map reset, not player-only resurrection. Experimental random-seed retry is a separately labelled option. Do not retain HP/ammo losses, invisible dead actors, opened optional doors or discovered map from prior attempt unless an explicitly different persistent-exploration experiment is chosen. Settings survive. Same inputs may reproduce the intended deterministic state only after fixed-step/RNG/event foundations are validated.

**Pause:** transition at a simulation boundary and stop the update/transaction path entirely; dt0 alone is insufficient. No pickup/door/completion/damage commit while paused. Hold active action ages, projectiles, AI, movers, authored light changes and music/voice transport; output/UI clock may continue. Role16 owns bounded click-safe transition, not per-voice rewinds. Map defaults paused per role17. Capture follows wall/display time, including paused card/duration. Mute is different: simulation/audio transport continue while user output gain changes.

**Resume:** reset wall-clock accumulator so elapsed pause cannot become catch-up damage. Remove initiating input until released; require fresh fire/use. Restore mouse only with actual focus; continue semantic action/music phase once without restarting tell. Modal stack and user preferences remain intact. No frame is simulated twice because device acknowledgement arrived late.

**Death:** health reaches0 in one ordered tick outcome; cancel uncommitted player/actor presentation releases as defined by shared event policy, stop further player actions, and enter result after an optional brief bounded death presentation. Gameplay cannot keep hurting the dead player or open progression behind the card. Freeze final authoritative state; music fades or approved defeat fragment, caption queue drops obsolete threat rows. Proposed presentation window0–0.5s is preference testing, not mechanical grace/automatic invulnerability. Retry/quit always responsive. If death and exit overlap same tick, proposed rule: finalize damage first; dead player cannot commit exit, unless an authored alternate rule is explicitly tested.

**Exit with surviving enemies:** shared C completion depends on entering its valid exit region, not killing all actors or clearing skipped P/T/O. At accepted transition increment/retire generation, freeze outgoing session, cancel pending world/audio/UI events, show result, release capture/controls according to recorder policy. No lingering enemy hits a player after result. A stateful exit's real prerequisites are authored per role07; user can see an available exit while threats remain. Leaving a combat region midfight in ordinary gameplay does not reset its actors; returning finds surviving state. Only profile retry resets the map. Optional skipped rooms/secrets cannot invalidate required exit or resource recovery.

## Saves: deferred scope with exact future contract

P M0/C first packet has **no disk checkpoint requirement**. Pause card says Retry from start; quit warns that this short run has no resume only where needed. An end result/session record is metadata, not a saved playable state. Once the accepted level is long enough to justify it, add authored checkpoint snapshots before arbitrary midcombat save.

Checkpoint record: save schema/content/build/profile IDs, tick/seed/RNG streams, stable entity state and action ages, player values, encounter dependency/skip state, unique inventory/pickup flags, doors/movers/exit/secret state, observed map knowledge and geometry revision. Include active projectiles only when their full owner/action/position/velocity/lifetime/event commitments are reconstructible. Absolute pointers, SDL device IDs, OpenGL textures, callback voice handles and UI widget tree never serialized. User settings remain separate. Dead/released/interrupt history cannot re-emit on load; transition into new runtime generation with saved semantic action state and imported watermark.

**Save mid-event:** snapshot only after a complete fixed-tick transaction batch, never between ammo deduction and shot/contact, switch flag and door effect, or damage and terminal cancellation. If actor is in windup, save age/action ID/commit state; restore its remaining tell and eventual release once. A launched projectile restores as flight, not another muzzle discharge. A moving door restores progress and obstruction rule against saved actors; validate support/clearance before publication. For first authored checkpoint policy, defer request until its declared safe boundary and show Pending; cannot silently advance while paused to reach it. Arbitrary mid-event saving is unsupported until these fixtures pass.

P write temp file in same writable directory, validate checksum/length/version, flush file and atomically replace target, preserve last known-good backup; durable Linux rename also needs directory fsync where required. Disk-full/interruption keeps old save and gives explicit failure; do not display Saved before completion. [Linux fsync documentation](https://www.man7.org/linux/man-pages/man2/fsync.2.html). Checksum detects damage, not malicious provenance or gameplay validity. Load into staging, check bounded record sizes/IDs/version/content compatibility; fail with recoverable message and preserve incompatible file. Schema migration requires reviewable mapping, no silent dropping keys/movers. Two concurrent game instances use a declared lock/conflict policy for saves/preferences, not last-writer corruption.

Exact musical waveform/cosmetic particles need not be bit-identically restored; explicitly restart at approved stable music entry and rebuild ambience from world state if that is the selected policy. Gameplay progress/cue truth is preserved; no claim of exact audio continuity from storing a bar label. Saved preferences are never rolled backward by an older checkpoint.
